# 결정트리와 부스팅 특징

---

## 1) 결정트리(Decision Tree) 소개

- 데이터를 계속 둘로 나누면서(**if–then 규칙**) 예측하는 트리 모양의 모델
- “어떤 기준으로 나눌 때 가장 깔끔해지나?”를 찾으며 분할을 반복 → 잎(leaf)에서 예측
- ex) `if (나이 < 30) and (최근 7일 레슨완료 ≥ 3) → 구독 전환 가능성 높음`

---

## 2) 결정트리 장단점

### 장점

- **설명 쉬움**: 규칙이 눈에 보임(그림/문장으로 공유하기 좋음)
- **전처리 부담 적음**: 스케일링·정규화 없어도 잘 작동
- **비선형/상호작용 자동 포착**: 변수 간 복잡한 관계를 분할로 자연스럽게 반영
- **예측 속도 빠름**: 추론 시 if–then만 따라가면 됨
- **특성 중요도 파악 가능**: 어떤 특징이 의사결정에 기여했는지 감 잡기 쉬움

### 단점

- **과적합 쉬움**: 트리가 깊어질수록 훈련셋만 잘 맞음 → 가지치기 필요
- **불안정성**: 데이터가 조금만 바뀌어도 트리 구조가 크게 달라질 수 있음
- **구간형(계단형) 예측**: 숫자 예측에서 매끈함 부족, 범위 밖 예측(외삽)에 약함
- **단일 트리 성능 한계**: 복잡한 문제에선 앙상블(랜덤포레스트/부스팅)이 더 강함

---

## 3) 결정트리 실무 사용 팁

- **언제 쓸까?**

  - 빠른 **베이스라인**/의사결정 규칙 도출, 설명이 중요한 프로젝트, 인터뷰/교육용

<br>

- **최소 튜닝 체크리스트**

  - `max_depth`(최대 깊이 제한), `min_samples_leaf`/`min_samples_split`(너무 작은 잎 방지)
  - 불균형 분류면 `class_weight="balanced"` 등 가중치 고려

<br>

- **자주 생기는 함정**

  - 트리 깊이 무한대 → 과적합
  - 카테고리의 희소 레벨(데이터 적은 값)에 과도하게 반응

<br>

- **간단 팁**

  - 교차검증으로 깊이·잎 크기 결정
  - 성능이 부족하면 **랜덤포레스트/부스팅**으로 즉시 확장

---

## 4) 머신러닝에서 부스팅(Boosting) 모델들은?

- **핵심 아이디어**: 약한 모델(대개 얕은 트리)을 **순서대로** 쌓으며, \*\*앞선 모델의 실수(오차)\*\*를 다음 모델이 고쳐나감

<br>

- **배깅 vs 부스팅**

  - 배깅(랜덤포레스트): 여러 모델을 **동시에** 학습해 평균 → "흔들림(분산)" 줄이기
  - 부스팅: 모델을 **차례대로** 학습해 이전 실수 보정 → 보통 "부족한 힘(편향)" 줄이기

<br>

- **데이터들중 부스팅이 왜 단일모델보다 잘 맞는게 있을까??**
  - **한 번의 분할 규칙으로 모든 걸 다 설명**하려다 보니, 훈련 데이터에만 딱 맟춰버려서 반대로 너무 단순해서 잘못 예측하는 경우가 많음
  - 부스팅은 약한 트리 여러 개를 **순서대로 연결**
  - **첫 번째 트리가 틀린걸 두 번째 트리가 보완** 이런식
  - **오류 보정 효과, 편향 감소, 다양한 특성이 반영**되고 앙상블 효과가 나타나서
  - 더 안정적이고 일반화된 성능을 보여줌

<br>

- **핵심 하이퍼파라미터**: `n_estimators`(트리 개수), `learning_rate`(한 트리의 반영 비율), 약한 트리의 크기(`max_depth`/`num_leaves`), (옵션) `subsample`/`colsample_*`

<br>

## 5) AdaBoost 이외의 주요 부스팅 — 특징·장단점·추천 상황

> 표형(tabular) 데이터 실무에서 가장 자주 쓰는 4총사: **Gradient Boosting, XGBoost, LightGBM, CatBoost**

| 모델                              | 한 줄 특징                                     | 장점                                  | 주의/단점                                | 추천 상황                             |
| --------------------------------- | ---------------------------------------------- | ------------------------------------- | ---------------------------------------- | ------------------------------------- |
| **Gradient Boosting**(sklearn)    | 손실의 \*\*기울기(잔차)\*\*를 다음 트리가 학습 | 개념이 명확, 구현 간단                | 속도·메모리는 대용량에서 한계            | 소규모/교육용, 기본 개념 실습         |
| **HistGradientBoosting**(sklearn) | 연속값을 **히스토그램 구간화**해 빠르게 분할   | 빠름, 결측·단조 제약 지원             | 옵션/생태계는 XGB/LGBM보다 적음          | 파이썬 표준도구 선호, 중형 데이터     |
| **XGBoost**                       | 정교한 정규화·희소최적화·풍부한 옵션           | **안정적 성능**, 문서/사례 풍부       | 파라미터 많아 튜닝 부담                  | 안정·재현성 중시 실무                 |
| **LightGBM**                      | **leaf-wise 분할**, GOSS/EFB로 고속·저메모리   | **매우 빠름**, 대용량·고차원 강함     | leaf-wise는 과적합 위험 → 깊이 제한 권장 | 속도·규모가 중요한 프로젝트           |
| **CatBoost**                      | **Ordered Boosting**, **범주형 자동 처리**     | 원-핫 최소, **카테고리 많아도 성능↑** | 학습시간이 길 수 있음                    | 범주형(고카디널리티) 많은 표형 데이터 |

## 6) 부스팅 실무 사용 팁

- **빠른 시작 레시피**

  1. 데이터 분할 + 교차검증
  2. `learning_rate` **작게**(예: 0.03\~0.1), `n_estimators` **크게** + **조기종료(early stopping)**
  3. 약한 트리 크기 제한(`max_depth≤6` 또는 `num_leaves` 적정)
  4. 필요 시 `subsample`/`colsample_*`로 무작위성 추가(과적합 완화)

<br>

- **데이터 팁**

  - 결측값: LightGBM/HistGBDT/CatBoost는 내부 처리 지원
  - 범주형: **CatBoost는 그냥 문자 컬럼로 넣어도 OK** / LightGBM은 `categorical_feature` 지정 또는 인코딩

- **불균형 분류**

<br>

- XGBoost `scale_pos_weight`, 클래스 가중치, 평가지표(PR-AUC/F1) 재설정

<br>

- **선택 가이드**

  - **속도/대용량**: LightGBM
  - **카테고리 많음**: CatBoost
  - **안정·레퍼런스 풍부**: XGBoost
  - **교육·표준 라이브러리**: (Hist)GradientBoosting

---

## 7) 마무리 요약(Takeaways)

- **결정트리**: 설명이 쉽고 전처리 부담이 낮지만, 과적합 쉬움 → 깊이·잎 크기로 제어
- **부스팅**: 이전 실수를 **순차적으로 보정**해 정확도를 끌어올리는 앙상블 → 하이퍼파라미터와 조기종료가 핵심
- **모델 선택 실전 규칙**: 표형 데이터는 보통 \*\*GBDT 계열(XGB/LGBM/CatBoost)\*\*이 강력. 데이터 특성(속도, 범주형, 안정성)에 맞춰 선택
- **항상**: 교차검증·적절한 지표·해석(특성 중요도/SHAP)로 검증
